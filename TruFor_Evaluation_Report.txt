1. INTRODUCTION
================================================================================

This report documents the systematic evaluation of the TruFor (Trustworthy
Forensics) model for image forgery detection and localization. TruFor is a
state-of-the-art deep learning model proposed by Guillaro et al. (2023) that
combines RGB image analysis with a learned camera-model fingerprint called
Noiseprint++ to detect and localize image manipulations including splicing,
copy-move, inpainting, and generative AI-based forgeries.

The evaluation was conducted across eight diverse image datasets representing
different real-world conditions across four transmission channels (Camera Sensor,
Instagram Social Network, Facebook Social Network, and Telegram Messenger):

  (a) DATA/REAL          - 25 high-resolution pristine camera images (compRAISE)
  (b) DATA/FAKE          - 25 inpainting-manipulated images (tampCOCO-style)
  (c) telegram_real      - 25 authentic images transmitted via Telegram
  (d) telegram_fake      - 25 manipulated images transmitted via Telegram
  (e) Instagram_Real     - 25 authentic images scraped from Instagram (WebP)
  (f) Instagram_Fake     - 25 manipulated images scraped from Instagram (WebP)
  (g) facebook_real      - 25 authentic images scraped from Facebook (JPEG)
  (h) facebook_fake      - 25 manipulated images scraped from Facebook (JPEG)

All experiments were run on:
  - GPU: NVIDIA GeForce RTX 5050 Laptop GPU (8 GB VRAM)
  - PyTorch: 2.12.0.dev20260408+cu128
  - Model Weights: pretrained_models/trufor.pth.tar (TruFor official release)


2. MODEL ARCHITECTURE OVERVIEW
================================================================================

TruFor employs a dual-branch encoder-decoder architecture:

  Branch 1 (RGB):         SegFormer-B2 backbone processing RGB pixel content
  Branch 2 (Noiseprint++): Learned camera sensor noise fingerprint extractor

The two branches are fused via a Cross-Modal Transformer (CMX) decoder that
produces three outputs:

  (i)   Anomaly Localization Map - Per-pixel tampering probability [0, 1]
  (ii)  Confidence Map           - Per-pixel prediction confidence [0, 1]
  (iii) Global Detection Score   - Whole-image integrity score [0, 1]
                                   (via confidence-weighted pooling)

The Noiseprint++ branch captures subtle inconsistencies in the camera sensor
noise pattern (PRNU - Photo Response Non-Uniformity). When a region of an
image is manipulated (e.g., pasted from a different source, generated by AI,
or in-painted), the noise pattern in that region differs from the rest of the
image, creating a detectable anomaly.


3. EXPERIMENTAL SETUP
================================================================================

3.1 Datasets
-------------

Dataset 1: DATA/REAL (compRAISE Pristine Images)
  - Source: compRAISE benchmark dataset
  - Format: PNG (lossless)
  - Resolution: 4928 x 3264 pixels (~16 Megapixels)
  - Count: 25 images
  - Ground Truth: All PRISTINE / AUTHENTIC (label = 0)
  - EXIF Metadata: Preserved (original camera sensor data)
  - Characteristics: High-resolution, uncompressed, full camera sensor
    noise preserved. Represents the ideal case for Noiseprint++ analysis.

Dataset 2: DATA/FAKE (Inpainting Manipulations)
  - Source: Inpainting-based forgeries (tampCOCO-style pipeline)
  - Format: PNG
  - Resolution: 246-500 pixels (max dimension 500)
  - Count: 25 images
  - Ground Truth: All TAMPERED / FAKE (label = 1)
  - Manipulation Type: Object inpainting (removal/replacement)
  - Characteristics: Small to medium resolution. Inpainting modifies only
    a localized region (typically 1-30% of total pixels), while the
    remaining image background is 100% authentic.

Dataset 3: telegram_real (Telegram Messenger Photos - Authentic)
  - Source: Authentic photos sent via Telegram messenger
  - Format: JPEG (Telegram-compressed)
  - Resolution: ~1279 x 847 pixels
  - Count: 25 images
  - Ground Truth: All PRISTINE / AUTHENTIC (label = 0)
  - EXIF Metadata: Stripped by Telegram
  - Characteristics: Images have been automatically downscaled and
    lossy JPEG compressed (Q ~75-80) by Telegram's media pipeline.
    This introduces compression artifacts that can confuse forensic
    models trained on clean camera sensor data.

Dataset 4: telegram_fake (Telegram Messenger Photos - Manipulated)
  - Source: Manipulated photos sent via Telegram messenger
  - Format: JPEG (Telegram-compressed)
  - Resolution: Various (Telegram-processed)
  - Count: 25 images
  - Ground Truth: All TAMPERED / FAKE (label = 1)
  - Characteristics: Tampered images that have been processed through
    Telegram's compression pipeline. Tests model robustness when forgery
    cues are degraded by double-compression and downscaling.

Dataset 5: Instagram_Real (Instagram Authentic Images)
  - Source: Authentic images from Instagram
  - Format: WebP (stored as .jpg)
  - Resolution: 1440 x 1440 pixels (standard high-res Instagram square)
  - Count: 25 images
  - Ground Truth: All PRISTINE / AUTHENTIC (label = 0)
  - Characteristics: Compressed using modern WebP encoding at high
    resolution (1440x1440), representing contemporary social media media.

Dataset 6: Instagram_Fake (Instagram Manipulated Images)
  - Source: Forged / altered images from Instagram
  - Format: WebP (stored as .jpg)
  - Resolution: 1440 x 1440 pixels
  - Count: 25 images
  - Ground Truth: All TAMPERED / FAKE (label = 1)
  - Characteristics: Manipulated imagery published and processed through
    Instagram's pipeline. Tests whether WebP encoding retains more forensic
    cues than Telegram's aggressive JPEG compression.

Dataset 7: facebook_real (Facebook Authentic Images)
  - Source: Authentic images from Facebook
  - Format: JPEG (Facebook-compressed)
  - Resolution: ~1080 x 715 pixels
  - Count: 25 images
  - Ground Truth: All PRISTINE / AUTHENTIC (label = 0)
  - Characteristics: Standard social network JPEG compression at 1080px
    standard resolution, testing Facebook's specific transcoding pipeline.

Dataset 8: facebook_fake (Facebook Manipulated Images)
  - Source: Manipulated images from Facebook
  - Format: JPEG (Facebook-compressed)
  - Resolution: ~500 x 335 pixels
  - Count: 25 images
  - Ground Truth: All TAMPERED / FAKE (label = 1)
  - Characteristics: Tampered images published on Facebook, subjected to
    Facebook's compression and downsampling.

3.2 Preprocessing
------------------

For high-resolution images exceeding GPU memory capacity (8 GB VRAM),
a memory-safe preprocessing pipeline was implemented:

  - Images are downscaled using LANCZOS interpolation to fit within a
    maximum dimension of 2048 pixels while preserving aspect ratio.
  - All dimensions are aligned to multiples of 8 (required by the
    SegFormer backbone's patch embedding).
  - CUDA memory cache is cleared between images to prevent OOM errors.

VRAM benchmarking results:
  Resolution      Peak VRAM Usage
  1024 x 680      1.76 GB
  1280 x 848      2.46 GB
  1536 x 1024     3.31 GB
  1792 x 1192     4.30 GB
  2048 x 1360     5.44 GB

The 2048 max_size limit was chosen as it fits comfortably within the
8 GB VRAM budget with margin for PyTorch overhead.

6. THRESHOLD CALIBRATION AND DUAL-CRITERIA DETECTION
================================================================================

6.1 The Problem with the Default 0.50 Threshold
-------------------------------------------------

The original TruFor inference script classifies images using a single
hardcoded threshold: score >= 0.50 → TAMPERED.

This threshold was designed for training benchmarks where manipulations are
typically large-area splices or copy-move attacks. However, for inpainting
manipulations (which modify only 1-30% of pixels), the whole-image pooled
detection score is diluted by the dominant authentic background.

Example:
  - Image "2860430876_large_4_inpainted-0.png" has a global score of 0.4355,
    but its anomaly localization map shows 26.56% of pixels with anomaly
    values > 0.5, with a peak anomaly of 0.9426. The model clearly detected
    the manipulation but the global score did not reach 0.50.

6.2 Calibrated Threshold Selection
------------------------------------

By analyzing the score distributions of DATA/REAL and DATA/FAKE:

  - 96% of REAL images score below 0.12
  - Maximum REAL score: 0.2606 (r15028ceft.png) — an outlier
  - Minimum FAKE score: 0.0736 — very subtle manipulation

The optimal threshold was determined via exhaustive sweep across the
combined REAL + FAKE evaluation set with dual-criteria enabled:

  Peak bACC threshold = 0.09, yielding:
    Sensitivity: 92.0% (23/25 FAKE detected)
    Specificity: 88.0% (22/25 REAL correct)
    Balanced Accuracy: 90.0%

  Selected practical threshold = 0.12, yielding:
    Sensitivity: 80.0% (20/25 FAKE detected)
    Specificity: 92.0% (23/25 REAL correct)
    Balanced Accuracy: 86.0%

The threshold of 0.12 was selected over 0.09 for practical deployment
because it reduces false positives on pristine images (2 FP vs 3 FP)
while maintaining strong fake detection (20/25 vs 23/25).

6.3 Dual-Criteria Detection
-----------------------------

To further improve detection of localized manipulations without
increasing false positives, a dual-criteria classification was implemented:

An image is classified as TAMPERED if EITHER:

  Criterion 1 (Global Score):
    Global detection score >= threshold (default: 0.12)

  Criterion 2 (Localized Anomaly):
    The confidence-weighted anomaly map shows:
    - Anomaly area (map > 0.5 AND conf > 0.5) covers >= 1% of total pixels
    - Peak anomaly value in the localization map >= 0.80

Rationale for Criterion 2:
  Even when the global score is low (due to a small tampered region being
  diluted by authentic background), the localization map retains high
  anomaly values in the manipulated area. By checking for coherent
  high-anomaly regions, we can detect subtle, localized manipulations
  that would otherwise be missed by the global score alone.

8.2 Deep Forensic Analysis: Why WhatsApp Preserves High Discriminability
------------------------------------------------------------------------

WhatsApp significantly outperforms Facebook (AUC: 76.6% vs 69.6%) and Telegram
(AUC: 76.6% vs 57.4%), achieving 100.0% specificity at tau = 0.30 (zero false
positives on authentic images). Discrete Cosine Transform (DCT) and pipeline
inspection reveal four technical reasons:

  1. Gentler DCT Quantization Matrix (Quality ~88-90 vs Facebook Q ~70-75):
     Header inspection of the raw JPEG luminance quantization matrices (Q) shows:
       - WhatsApp Q-table (first 10 bins):  [3, 2,  2,  3,  4,  6,  8, 10, 2,  2]
       - Facebook Q-table (first 10 bins):  [9, 8, 16, 16, 23, 24, 26, 27, 8, 11]
     Facebook's quantization divisors are 3x to 4x higher. High divisors discard
     subtle high-frequency noise and force stark 8x8 block boundary seams that
     trigger false alarms in Noiseprint++. WhatsApp's low divisors preserve fine
     pixel-to-pixel micro-noise, keeping authentic baseline scores down to 0.1414.

  2. Higher Spatial Resolution Cap (1.7 MP vs 0.77 MP):
     - WhatsApp preserves up to 1600px along the major axis (~1600x1059 = 1.69 MP).
     - Facebook restricts web photos to 1080px (~1080x715 = 0.77 MP), discarding
       over 54% of total pixels.
     - Telegram downsamples to ~1279x847 (~1.08 MP).
     The higher pixel count preserves spatial tampering boundaries for SegFormer.

  3. Single-Hop Direct Transcoding vs Multi-Tier CDN Recompression:
     - WhatsApp applies a single client-side transcode directly upon transmission.
     - Facebook routes media through a multi-tier CDN caching pipeline that applies
       iterative recompression and dynamic downsampling, acting as an anti-forensic
       filter that erases the camera's Photo-Response Non-Uniformity (PRNU).

  4. Exceptional Separation Gap (Delta Mean = +0.1791):
     Because authentic WhatsApp media sits at 0.1414 (with max score 0.2963),
     and tampered media reaches 0.3205 (max 0.9830), the distributions remain
     well-separated, allowing tau = 0.30 to operate with zero false alarms.


8.3 Implications for Forensic Practice and Research
----------------------------------------------------

  (a) Uncalibrated Deployment Danger: Deploying a threshold calibrated on
      pristine benchmarks (tau = 0.12) to social media content results in
      an 88.0% - 92.0% false alarm rate on Facebook and Telegram.

  (b) Platform-Specific Threshold Calibration: Forensic tools must not apply
      a single global threshold. The detection threshold must be dynamically
      selected based on the media source.

  (c) Transmission Codec Sensitivity: Modern compression (WebP / high-quality
      1600px JPEG) preserves substantial forensic utility, while aggressive
      low-resolution DCT quantization wipes out forensic traces.

12.1 Motivation & Forensic Rationale

In real-world digital forensics and deepfake investigation, contested multimedia
is rarely acquired directly from native camera sensors. Instead, the vast majority
of digital evidence is intercepted or harvested from social media and messaging
networks (WhatsApp, Instagram, Facebook, and Telegram).

channels impose destructive transformations on image bitstreams:

12.3 Software Architecture & Core Engineering
----------------------------------------------
The simulator is implemented as a lightweight, high-performance web service
contained entirely inside the SIMULATOR/ directory:

  e:\DeepFake\TruFor-main\SIMULATOR\
    ├── server.py        # Python Flask backend server & compression engine
    ├── index.html       # Single-page application structure & UI markup
    ├── styles.css       # Clean Apple/Vercel light aesthetic styling
    ├── script.js        # Interactive client logic & API communications
    ├── mountains.jpg    # Default reference asset matching visual specification
    ├── uploads/         # Ephemeral upload buffer for client sessions
    └── output/          # Transcoded simulation assets and difference heatmaps

Core Algorithmic Components in server.py:

(1) Automatic Orientation & Alpha Compositing Pipeline:
    Modern mobile smartphones (iPhone, Samsung, Google Pixel) record raw CMOS
    sensor arrays in landscape orientation, appending an EXIF Tag 274 (Orientation = 6)
    when held vertically. Naive PIL Image.open() ignores this tag.
    The simulator implements prepare_image_for_processing():
      - Evaluates ImageOps.exif_transpose(img) immediately upon file ingestion.
      - Transposes raw pixel arrays into correct display orientation (e.g., 3060x4080 portrait).
      - Composites transparent RGBA/palette PNG inputs against a solid white background
        prior to lossy JPEG compression, preventing transparent regions from converting
        to destructive black blocks.
      - Ensures Card 1 (Original) and Card 2 (Simulated) remain in 100% spatial alignment.

(2) Empirical Platform Transcoder (compress_image):
    - Reads profile parameters for the selected platform and quality tier.
    - Scales image using high-order Lanczos downsampling while strictly preserving
      original aspect ratios:
        scale = max_dim / max(width, height)
        (new_w, new_h) = (int(orig_w * scale), int(orig_h * scale))
    - Injects empirical 64-element DQT arrays into the JPEG bitstream header with
      2x2 chroma subsampling (subsampling=2).
    - Encodes WebP for Instagram using method 4 vector optimization.

(3) Inferno Forensic Difference Heatmap Engine (compute_difference_map):
    To visualize subtle compression artifacts, blocking boundaries, and edge
    ringing introduced by platform transcoding, the backend computes:
      diff(x, y) = (1/3) * sum_{c in {R,G,B}} |I_orig(x,y,c) - I_comp(x,y,c)|
    A non-linear power-law gamma expansion amplifies subtle differences:
      diff_boosted = ((diff / 255.0) ** 0.65) * 255.0 * 2.8
    The resulting scalar intensity is mapped through a 256-color Inferno LUT:
      Dark Violet (#0b011d) -> Indigo (#420a68) -> Crimson (#dd513a) -> Bright Yellow (#fbf246)
    This provides an intuitive forensic visualization: authentic regions with
    near-zero distortion appear deep black/violet, while compression boundaries,
    displaced DCT blocks, and ringing artifacts glow crimson and yellow.

(4) Visual Error Rating Metric (rate_visual_difference):
    Computes global mean L1 pixel difference and assigns qualitative forensic tiers:
      - Minimal:  mean_diff < 2.0  (Near-identical perceptual fidelity)
      - Low:      mean_diff < 5.0  (Minor loss in ultra-high frequency textures)
      - Moderate: mean_diff < 12.0 (Noticeable smoothing / slight edge softening)
      - High:     mean_diff < 22.0 (Obvious blocking / color degradation)
      - Severe:   mean_diff >= 22.0 (Destructive distortion)

12.9 Phase 2 Re-Evaluation: Splicing / CASIA Benchmark & Test Sets (October 2026)
---------------------------------------------------------------------------------
On October 5, 2026, a full re-evaluation of TruFor was conducted following the
curation of an updated forgery benchmark.

(a) Forensic Shift: Inpainting vs Splicing Manipulations:
    In the initial September 15 baseline (documented in Sections 4-8), fake images
    consisted of localized inpainting (tampCOCO pipeline, e.g. 120545126_medium_4_inpainted-0.png).
    In subtle inpainting, only 1-5% of pixels are modified while 95%+ of the original
    sensor PRNU pattern remains intact. Lossy platform compression smoothed over
    these delicate boundaries, suppressing sensitivity to 36% (WhatsApp) and 20% (Telegram).

    In the Phase 2 dataset, manipulated images were replaced with CASIA / FantasticReality
    splicing attacks (Sp_D_CNN_... and Sp_D_CND_...). Splicing combines image regions
    from two completely different cameras, creating a macro-level collision between
    discrepant PRNU noise fingerprints. Because the fingerprint disparity is structural
    rather than delicate, it survives aggressive social media transcoding.
